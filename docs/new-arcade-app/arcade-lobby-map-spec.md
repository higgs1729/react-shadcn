## この文書の役割

新アーケードアプリが再利用する「3Dアーケードロビー」を、現状の単一の箱型ルームから
**ゾーン分割された“ちゃんとしたマップ”**へ刷新するための計画とビジュアル仕様を定める。
ゲームのルールや弾幕仕様はここでは扱わない（それは収録ゲーム側の文書）。

刷新は再利用元 `apps/team-t` の3D基盤（`team-t-world-*.tsx`）で先に実装し、
`apps/arcade` 新設時にアプリ非依存部分として抽出する。README の再利用方針に従う。

## 確定した方向（人間の選択）

| 論点 | 決定 |

## 現状のマップ資産と課題（刷新前）

再利用元 `apps/team-t` の実装:

- `lib/team-t-app/world.ts` — 16×12（半寸）ルーム、9筐体を奥壁5＋左右2ずつ、難易度順配置。ゲーマーアバター、帰還ゲート
- `team-t-world-room.tsx` — 8×6の市松床＋素の壁（ドア/窓/角/柱）＋点光源3
- `team-t-world-canvas.tsx` — 追従カメラ、環境光/半球光/平行光、`FogExp2`、`frameloop` 一時停止
- `team-t-world-kiosk.tsx` — Kenney 実機GLB＋足元リング＋近接ラベル
- アセット: Kenney Mini Arcade 1.2 一式（`public/world/models/arcade/`、約1.0MB、CC0）

**「すごくない」要因**:

1. **単一の箱**で区画も回遊もない。筐体は壁に貼り付き、中央は空きの市松床のみ
2. **装飾が皆無**（座席・景品カウンター・自販機・看板・ポスター・天井・観葉植物・のれん・提灯なし）
3. **照明が静的3点**。発光する筐体画面・ネオン看板・ブルーム・床反射がない
4. **無人で動きがない**（NPC・アトラクト画面・環境の微動なし）
5. **和の要素ゼロ**。製品の月夜・神社アートと世界観が断絶

## ビジュアルターゲット / ムード

**「夜の和風ゲームセンター」**。濃紺の闇に、朱の提灯・金の行灯・紫マゼンタのネオン筐体が浮かび、
奥の大窓からは弾幕ゲームと同じ**満月**が覗く。床は濡れたように筐体の光を反射し、
入口には小さな**鳥居門**と**暖簾**。天井から提灯が連なる。低ポリだが、光と密度で“場”を作る。

配色の中心は既存パレットを継承しつつ和へ寄せる:

- 地: 濃紺〜黒 `--void:#05030a`
- 光の主役: 朱（提灯）・金 `--gold:#d8bf88`（行灯・構造）・紫 `--amethyst:#9b6cff`／マゼンタ `--magenta:#d84bff`（筐体ネオン）
- 木目・格子は低彩度の暗褐、暖簾は朱。危険な原色の氾濫は避け、コントラストは筐体画面と看板に集約

弾幕ゲーム側の「濃紺・朱・象牙・金」と同じ色域を共有し、ロビーとゲームが地続きに見えるようにする。

## 空間設計: ゾーンとレイアウト

単一の箱を、**主動線でつながった4ゾーン**へ再構成する。プレイヤーは入口から入り、
メインフロアの筐体島を回遊し、脇に景品カウンターとラウンジを見る。

```text
                 ┌───────────── 奥（-Z）: 大窓＋満月 ─────────────┐
   [景品カウンター]      ■ ■ ■   （筐体島 A）        [休憩ラウンジ]
   受付NPC・棚・         ■ ■ ■   （筐体島 B）        ソファ・卓・
   景品・両替機          ┊ 中央主通路 ┊                観葉・自販機・行灯
                 ┌───── 入口ゾーン: 鳥居門・暖簾・歓迎看板・帰還ゲート ─────┐
                 └───────────── 手前（+Z）: プレイヤー入場 ────────────┘
```

### ゾーン一覧

| ゾーン | 役割 | 主要プロップ（低ポリ＋手続き的） |
| --- | --- | --- |
| 入口 | 入場・帰還ゲート・世界観の第一印象 | 手続き的**鳥居門**、**暖簾**（ドア上）、歓迎ネオン看板、下足マット。帰還ゲートはここに置く |
| メインフロア | 筐体を**島配置**で回遊。ロビーの主役 | ゲーム筐体を2〜3列の島に。島間に通路。頭上に提灯の列、床にゾーン別カーペット |
| 景品カウンター | 賑わいと目的地感 | 受付カウンター、棚＋景品（Mini Market/Arcade）、両替機・チケット機、受付NPC（employee） |
| 休憩ラウンジ | 密度と生活感、休符 | ソファ・ローテーブル・観葉植物（Furniture Kit）、自販機・冷蔵ケース（Mini Market）、行灯、待機NPC |

### 動線（回遊）

- 入口→中央主通路→奥（満月の窓）へ抜ける明快な背骨を1本通す
- 主通路の左に景品カウンター、右にラウンジ（左右は入替可）
- 筐体島は主通路から各面へアクセスでき、袋小路を作らない
- 床のカーペット色とゾーン別ネオン看板で**道標**にする（メインは紫、景品は金、ラウンジは朱）

### 機械スロット方式（再利用のための脱・Team T結合）★重要

現状の `teamTWorldKiosks` はTeam Tの9ゲームにハードコードされている。新アプリは初期2ゲーム。
**マップの空間設計（ゾーン・床・壁・プロップ・照明）を、機械の中身（どのゲーム/何台）から分離する。**

- マップは**筐体スロットの配列**を持つ（島Aに3、島Bに3…のような座標・向き・スケールの定義）
- 各アプリがスロットへ中身を割り当てる:
  - Team T: 9スロットに9ゲームを割当（現状維持）
  - 新アプリ: 2スロットに実ゲーム（bullet-hell / neon-tunnel）、**残りは非対話の“アトラクト筐体”**として賑わい要員に
- これにより、収録数が少ない新アプリでも**フロアが常に埋まって見える**。空きスロットが致命的な空白にならない

この分離は今回の刷新で必ず入れる（マップを両アプリで再利用する前提の骨格）。

### 新規（すべてCC0・Phase Aで取得・parse確認・CREDITS追記）

| パック | 用途 | 取るモデルの例 |
| --- | --- | --- |
| Kenney Furniture Kit | ラウンジ | ソファ・アームチェア・ローテーブル・観葉植物・ラグ・フロアランプ |

### 手続き的な和風シグネチャ（アセット追加なし・照明で魅せる中核）

モデルを増やさず、`PlaneGeometry`／基本ジオメトリ＋加算合成＋発光で作る（`neon-tunnel.html` の実証方式）:

- **鳥居門**（入口）: 柱2＋笠木2の単純ジオメトリ、朱マテリアル＋縁に金ネオン
- **提灯の列**（天井・通路上）: 発光する円筒／球、朱〜金。reduceMotion offで微揺れ
- **行灯**（ラウンジ）: 木枠＋和紙面の暖色発光ボックス
- **暖簾**（ドア上）: 朱の面2〜3枚、下端だけ揺らす
- **満月＋夜空**（奥の大窓の外）: 発光ディスク＋濃紺グラデ面。弾幕ゲームの月と同モチーフ
- **ゾーン別ネオン看板**: 「遊技」「景品」「休憩」等の発光板（日本語）

### 予算

- **容量上限は撤廃（合意済み）**。`public/world/` のサイズを見た目のために制約しない。
  ただし低ポリ・CC0の方針は維持し、初期ロードとメモリの実測は Phase D で行う
- 反復プロップ（床タイル・椅子・提灯）は**インスタンシング/共有ジオメトリ**で描画コストを抑える

## 照明・マテリアル・ポスト処理（“すごい”の主戦場）

低ポリを高見えさせる中核。ここに一番投資する。

1. **発光する筐体画面**: 各実機のスクリーン面に emissive／加算平面を貼り、機種別の色でアトラクト発光
2. **ネオン看板・提灯・行灯**: 加算合成の発光面。`toneMapped=false` で白飛びさせず色を保つ
3. **月光**: 奥窓から差す方向光＋窓面の発光。室内に青白い斜光の芯を作る
4. **床反射**: 濡れた床の反射で筐体ネオンを倍増（drei `MeshReflectorMaterial` を低解像度で、または簡易フェイク反射）。性能次第でメインフロアのみに限定
5. **ブルーム**: `@react-three/postprocessing` の `EffectComposer`＋`Bloom`＋弱い `Vignette`。**発光要素の“光の滲み”を作る最大のレバー**。新規依存の追加（バンドル増）は要合意
6. **天井**: 暗い天井＋提灯／ダウンライトで**閉じた室内感**を出す（現状は開いた天井の箱）
7. **フォグ**: 奥行きと世界の縁を消す。窓の満月だけ霧の先に浮かせる

reduceMotion時（Team T設定を尊重）: アトラクトの明滅・提灯の揺れ・カメラのラグ/スウェイを止め、静止した夜の店にする。3D自体は必ず出す（例外化の既存方針を継承）。

## 賑わい・アニメーション

- **待機NPC**: `character-gamer`／`character-employee` を既存スキン機構で色替えし、筐体前・受付に数体。待機アニメ再生（reduceMotion時は静止ポーズ）
- **アトラクト画面**: 筐体スクリーンの発光色を低速サイクル
- **環境の微動**: 提灯・暖簾の揺れ、行灯のゆらぎ、床反射のわずかな揺らぎ
- 音は初期スコープ外（README未決に従う）

## 性能予算

初期目標は一般的なデスクトップで安定60fps。

- 追従カメラ・単一プレイヤー・室内規模を維持。`frameloop` はプレイ中 `never` で停止（既存）
- 反復プロップはインスタンシング。ドローコールを機種・プロップ種ごとに集約
- 床反射は解像度と対象面を絞る。効かなければメインフロア限定→最終手段で無効化
- ブルームは1パス。全画面ブラーや常時色収差は使わない
- `three`/r3f/postprocessing は `next/dynamic(ssr:false)` の遅延チャンクに閉じる（初期バンドルに載せない）
- 不足時の削減順: ①画面外NPC/微動を止める ②床反射を切る ③ブルーム品質を落とす ④提灯本数を減らす。**筐体・帰還ゲート・プレイヤーの視認性は最後まで守る**

## 守るべき契約（不変）

刷新は見た目と空間の話。ゲーム起動の骨格は壊さない。

- **筐体選択→ブリーフィング→起動→終了→ロビー復帰**の遷移（`team-t-game-runtime.tsx` 契約）
- 近接判定（`ProximityProbe`）と帰還ゲート（`team-t-world-exit-gate.tsx`）
- `frameloop` 一時停止による再読込回避
- 9筐体はスロットへ移すだけ。座標が変わっても近接・ラベル・起動は据え置き

新アプリでは README 通り `game:ended` のコイン契約を引き継がず、最小契約へ再定義する。マップはその契約に非依存。

## apps/arcade への再利用設計

- 空間（ゾーン・床・壁・プロップ・照明・和風シグネチャ）を**アプリ非依存**に保つ
- アプリ依存は「スロットに割り当てる機械リスト」と「起動する実ゲーム」だけ
- Team T固有（コイン/報酬/カタログ/難易度順）をマップ本体へ混ぜない
- 共通化のパッケージ抽出時期は README 未決に従い、**2アプリで同一責務が確認できてから**

## 受け入れ条件

- 入口・メインフロア・景品・ラウンジの**4ゾーンが視認でき**、主通路で回遊できる
- 鳥居門・暖簾・提灯・行灯・満月窓が存在し、**夜の和風ゲームセンター**に見える
- 筐体が**島配置**で、壁貼り付きでない。頭上・床・看板でゾーンが読める
- 発光筐体画面・ネオン看板・ブルーム・床反射で低ポリが高見えする
- 待機NPCとアトラクトで**無人でない**（reduceMotion時は静止）
- 筐体起動→復帰、帰還ゲートの契約が従来どおり動く
- **機械スロット方式**により、2ゲームだけの新アプリでもフロアが埋まって見える
- 静的exportで起動し、外部CDNに依存しない。`three` 系は初期バンドルに載らない
- `public/world/` が予算内、一般デスクトップで60fps
