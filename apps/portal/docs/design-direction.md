# Portal (`/`) デザイン方針

`/` は、サイトで扱う制作物のうちブラウザ上で実際に利用できるアプリを集めた入口。実体は `components/landing-hub.tsx`。

## 役割

- ウェブ上で利用できるトップレベルのアプリと、その用途を一覧化する。
- 各アプリへ直接移動できる一次導線を提供する。
- ウェブ外の制作物や文書は、この一覧へ混在させない。
- アプリ内機能を別アプリとして重複掲載しない。
- アプリ固有の状態や設定をポータルへ持ち込まない。

## 情報設計

トップレベルは次の3アプリから始め、追加時も同じ縦一覧へ行を増やす。

| アプリ                    | 目的                 | 一次導線            |
| ------------------------- | -------------------- | ------------------- |
| AI Design System Studio   | UI設計の過程を見る   | `/studio/overview/` |
| Team T                    | 公開APIを探して試す  | `/team-t/`          |
| データ分析試験 模擬問題集 | Python試験を練習する | `/python-test/`     |

## 表現

- ヘッダーは黒背景で固定し、現時点では `higgs1729` だけを置く。
- 背景は暖色寄りのオフホワイト、本文とCTAは黒、装飾アクセントは朱色、通常リンクは青を使う。
- ヒーローは直交座標と積分領域を静かな数学的モチーフとして使い、主文言は「公開中のアプリを、今すぐ使おう。」とする。
- 意図した改行は読点「、」の直後だけに置く。
- アプリ一覧は `アプリ一覧 = [ { ... }, ]` のJSON風構造で表現する。
- 番号・統計チップ・関連リンクを置かず、各行はロゴ、用途、名称、説明、一次CTAだけで構成する。
- 最終行の仕切り線は閉じ角括弧 `]` の上に置き、角括弧の下には仕切り線を置かない。
- CTAは黒背景、実リンクである「ページ上部へ」は青で表示する。

## 技術境界

- `LandingHub` は server component のまま保ち、状態・client hookを追加しない。
- ヒーローのx軸・y軸・原点・積分曲線は、画像内の軸位置を共通原点へ固定した単一の座標系として扱う。画面幅ごとに各画像を個別移動させない。
- 軸ラベル `O` / `x` / `y` は元画像から固定ピクセル寸法で表示し、画面幅に追従して拡大縮小しない。
- 積分曲線は全幅で同じ高さを保ち、狭い幅では透明度と横方向の配置だけを調整する。素材内部の積分基準線をx軸へ合わせる。
- クロスアプリ遷移は素の `<a>` と `NEXT_PUBLIC_BASE_PATH` prefixを使う。
- LPの見た目は `landing-hub.tsx` 内に閉じ、共有トークン・`components/ui/*`・各アプリを変更しない。
- GitHub Pagesの静的exportとtrailing slashを維持する。
