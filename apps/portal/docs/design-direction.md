# Portal (`/`) デザイン方針

`/` は、サイトで扱う制作物のうちブラウザ上で実際に利用できるアプリを集めた入口。実体は `components/landing-hub.tsx`。

## 役割

- ウェブ上で利用できるトップレベルのアプリと、その用途を一覧化する。
- 各アプリへ直接移動できる一次導線を提供する。
- ウェブ外の制作物や文書は、この一覧へ混在させない。
- アプリ内機能を別アプリとして重複掲載しない。
- アプリ固有の状態や設定をポータルへ持ち込まない。

## 情報設計

トップレベルは次の4アプリから始め、追加時も同じ縦一覧へ行を増やす。

| アプリ                    | 目的                 | 一次導線             |
| ------------------------- | -------------------- | -------------------- |
| Team T API Lab            | 公開APIを探して試す  | `/team-t/`           |
| AI Design System Studio   | UI設計の過程を見る   | `/studio/overview/`  |
| データ分析試験 模擬問題集 | Python試験を練習する | `/python-test/`      |
| GAMEHUB                   | ブラウザゲームで遊ぶ | リポジトリ内のソース |

## 表現

- ヘッダーは黒背景で固定し、現時点では `higgs1729` だけを置く。
- 背景は暖色寄りのオフホワイト、本文とCTAは黒、装飾アクセントは朱色、通常リンクは青を使う。
- ヒーローは直交座標と積分領域を静かな数学的モチーフとして使い、主文言は「公開中のアプリを、今すぐ使おう。」とする。
- 意図した改行は読点「、」の直後だけに置く。
- アプリ一覧は `アプリ一覧 = [ { "name": "..." }, ]` のJSON風構造で表現し、アプリが増えても一項目一行を維持する。
- 左ツリーは連続した行番号、ロゴ、`"name"` キー、名称で構成する。選択行は背景と左ガターで示し、開閉用caretは置かない。
- 座標のy軸はコンテンツの外枠として扱い、行番号を含むアプリ一覧と右ペインをすべてy軸の内側に収める。
- カンマは最終項目以外にだけ付け、閉じ角括弧 `]` は最終項目の直下一行に置く。
- 右ペインは選択中アプリのJSON風概要・説明・一次CTAと代表画面の2カラムで構成する。長い選択アプリ名は省略せず、キーと値を分けたグリッド内で自然に折り返す。概要と代表画面の間には明確な余白を設ける。
- 代表画面は縦横比を保ち、最大幅670px・最大高530pxとする。枠線・影・可視ラベルは付けず、暖色ニュートラルの背景面と12pxの内側余白でプレビュー領域としてまとめる。
- 右ペインの実幅が46rem以下では概要と代表画面を縦積みに切り替え、画面比率によって代表画面だけが極端に縮小される状態を作らない。
- CTAは黒背景、実リンクである「ページ上部へ」は青で表示する。

## 技術境界

- `LandingHub` は server component のまま保ち、状態・client hookを追加しない。例外は `components/json-list.tsx` の表示状態(入れ子の開閉・右ペインの選択・ドリルダウン)だけで、これは枠の内部に閉じている。
- ヒーローのx軸・y軸・原点・積分曲線は、画面全幅に固定した単一の座標系として扱う。座標系だけを中央寄せしたmax-widthコンテナへ入れない。
- 本文左端と原点は同じ画面端基準のトークンで管理し、原点は最大124px、本文左端は最大188pxとして、広い画面でも両者の間に64px以上を確保する。
- x軸は左右端から直接配置し、原点や要素幅に依存した割合translateで始点を算出しない。
- 軸ラベル `O` / `x` / `y` は元画像から固定ピクセル寸法で表示し、画面幅に追従して拡大縮小しない。
- 積分曲線は全幅で同じ高さを保ち、狭い幅では透明度と横方向の配置だけを調整する。素材内部の積分基準線をx軸へ合わせる。
- クロスアプリ遷移は素の `<a>` と `NEXT_PUBLIC_BASE_PATH` prefixを使う。
- LPの見た目は `landing-hub.tsx` 内に閉じ、共有トークン・`components/ui/*`・各アプリを変更しない。
- GitHub Pagesの静的exportとtrailing slashを維持する。
