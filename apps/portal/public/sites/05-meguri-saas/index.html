The problem

解約は、
四つの兆候のあとに来る。

定期便の解約は、ある日突然は起きません。 その前に必ず、いくつかの小さな信号が出ています。 問題は、それらが管理画面・決済代行・カスタマーサポートに散らばっていて、 誰も一つの流れとして見ていないことです。

SIGNAL 01

スキップが二回続く

一度のスキップは旅行や在庫過多で起きます。 二回続いたときの解約率は、そうでない場合の 4.1 倍です。

SIGNAL 02

お届け間隔を伸ばす

4週から8週への変更は、多くの場合「やめる前の様子見」です。 変更操作の直後は、まだ気持ちが残っています。

SIGNAL 03

決済が失敗する

カードの有効期限切れは、意思のない離脱です。 通知が届かないまま、3回目の失敗で自動解約になる例が最も多いパターンです。

SIGNAL 04

問い合わせのあと沈黙する

返信内容ではなく「そのあと何も起きていない」ことが信号です。 対応済みフラグは、解決したことを意味しません。

Features

拾って、つなげて、渡す。

新しいことをするための道具ではありません。 すでに起きていることを、担当者が動ける形にして届けます。

F-01

解約予兆スコア

四つの信号と購入履歴から、顧客ごとに 0〜100 のスコアを毎日更新します。 しきい値を超えた顧客だけが一覧に上がります。

更新: 毎日 04:00 JST

F-02

スキップ理由の収集

マイページのスキップ操作に一問だけ差し込みます。 選択式のみ、平均回答率は 68%。理由別の推移がそのまま集計されます。

導入: タグ1行

F-03

決済リトライ

失敗した決済を、カード会社ごとの成功率が高い時間帯に再試行します。 同時に、更新用のリンクをメールと SMS で送ります。

対応: Stripe / GMO / Square

F-04

配送スケジュール

すべての定期便を1枚のカレンダーで見ます。 在庫の引き当てと突き合わせ、欠品が出る週を事前に警告します。

粒度: 週次 / 日次

F-05

LTV とコホート

初回接点別・商品別のコホートを自動生成します。 広告経由と自然流入で継続率がどれだけ違うかが、初月から見えます。

出力: CSV / API

F-06

アクションの記録

誰がいつ、どの顧客に何をしたか。効果があった打ち手だけが残るように、 結果と紐づけて記録します。

連携: Slack / メール
