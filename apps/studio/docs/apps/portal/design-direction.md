# Portal (`/`) デザイン方針

`/` は複数アプリの最上位入口。実体は `components/landing-hub.tsx`。
装飾を見せるポートフォリオではなく、目的からアプリを選び、迷わず開けるディレクトリとして扱う。

## 役割

- トップレベルのアプリと、その用途・主機能を一覧化する。
- 各アプリへ直接移動できる一次導線を提供する。
- アプリ内機能を別アプリとして重複掲載しない。
- アプリ固有の状態や設定をポータルへ持ち込まない。

## 情報設計

トップレベルは次の3アプリに限定する。

| #   | アプリ                    | 目的                 | 一次導線        |
| --- | ------------------------- | -------------------- | --------------- |
| 01  | AI Design System Studio   | UI設計の過程を見る   | `/overview/`    |
| 02  | Team T                    | 公開APIを探して試す  | `/team-t/`  |
| 03  | データ分析試験 模擬問題集 | Python試験を練習する | `/python-test/` |

`Neon Tunnel` は Team T 内の機能なので、Team T 行の関連リンクとして扱う。
Studio の Patterns / Quality も同様に関連リンクへ置く。

## 表現

- 日本語を主言語にし、「何ができるか」を具体的に書く。
- 巨大な装飾アート、outline文字、グラデーション、意味のない英語コピーを使わない。
- warm gray の背景、白い情報面、濃色の本文、青一色のアクセントで構成する。
- アプリはカードのギャラリーではなく、番号付きの縦一覧として比較できるようにする。
- CTAは各アプリに一つ。副導線は本文下のテキストリンクに下げる。
- hoverは色反転程度に留め、情報の読みやすさを優先する。

## 技術境界

- `LandingHub` は server component のまま保ち、状態・client hookを追加しない。
- クロスアプリ遷移は素の `<a>` と `NEXT_PUBLIC_BASE_PATH` prefixを使う。
- LPの見た目は `landing-hub.tsx` 内に閉じ、共有トークン・`components/ui/*`・各アプリを変更しない。
- GitHub Pagesの静的exportとtrailing slashを維持する。
